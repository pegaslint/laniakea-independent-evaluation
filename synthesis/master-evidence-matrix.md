## 1. Status and evidence vocabulary

### Repository grades and workflow status

Faithful summaries of `EVAL-CHARTER.md` — Grades:

| Repository grade | Meaning |
|---|---|
| PASS | The pre-stated invariant is established at the pinned snapshots. |
| WARN | The invariant is at risk, ambiguous, incompletely documented or materially stale without direct contradiction sufficient for FAIL. |

### Claim classes and temporal scope

`EVAL-CHARTER.md` — Claim-status classes and `expected/L1.md` — Claim classes distinguish CURRENT-GOVERNANCE, CURRENT-IMPLEMENTATION, CURRENT-DEPLOYED and CURRENT-OPERATIONAL assertions from PROPOSED, TARGET-ARCHITECTURE, ROADMAP, CONCEPTUAL, DEPRECATED/HISTORICAL and AMBIGUOUS material. The first group describes what a source asserts is current, not what the evaluation has proven; the other classes preserve future, conceptual, historical or unresolved status.

The unchanged L1 reporting crosswalk in `reports/2026-09-18-f438819/L1-claim-map.md` — Classification and evidence rules is used below:

| L1 reporting class | Interpretation |
|---|---|
| CURRENT-GOVERNANCE | Documentary assertion about current governance, tested against Atlas only within authorized scope. |
| CURRENT-IMPLEMENTATION | Assertion of existing implementation; L1 would also place a bare deployment-existence assertion here with deployment explicitly noted, without equating code and deployment. |
| CURRENT-OPERATIONAL | Assertion of ongoing operation, use or an operational configuration state. |
| PROPOSED-TARGET | Crosswalk for PROPOSED, TARGET-ARCHITECTURE and conceptual/specification material, preserving their qualifications. |
| FUTURE-ROADMAP | Crosswalk for ROADMAP, including unscheduled/far-future scope. |
| HISTORICAL | Crosswalk for DEPRECATED/HISTORICAL; does not promote old material to current authority. |
| EXAMPLE / ILLUSTRATIVE | Worked examples and hypothetical prerequisites; an illustrative pattern can coexist with a separate running-instance claim. |
| AMBIGUOUS | Wording does not establish a sufficiently clear current/future or implementation/activation scope. |

A future/target/conceptual claim does not fail because it is unimplemented. Draft normative language is not evidence of enacted governance, deployed settings or operational enforcement.

### Synthesis dispositions

| Synthesis disposition | Definition in this matrix |
|---|---|
| ESTABLISHED | The row's explicitly scoped conclusion is supported: this can be documentary framing, a documented discrepancy, or bounded implementation/chain support, never an unstated universal claim. |
| PARTIALLY ESTABLISHED | Identified subclaims or intermediate provenance edges are supported while material parts remain unresolved or inconsistent; the repository result is retained separately. |
| NOT ESTABLISHED | The accumulated evaluation does not establish the scoped proposition or mapping. |
| TARGET DESIGN | The evaluated statement remains proposed, conceptual, target or future/roadmap design, protected from an implementation-failure inference. |
| NOT INDEPENDENTLY VERIFIED | A source assertion is preserved, but independent substantive verification was deferred, blocked or not undertaken in the evaluation. |
| OUT OF SCOPE | The proposition's broader truth test is outside the completed substantive verification scope; documentary ambiguity can still be recorded. |
| PARKED | Further verification is set aside pending a specified new evidence lead; for C06 this does not replace its repository NOT ESTABLISHED result or chain HOLD. |

“—” means a layer is not applicable to the row's tested documentary/design question. “NOT TESTED” means a potentially relevant layer was not substantively evaluated. Neither means failure. Evidence depth in section 3 lists inspected layers, not numeric confidence, certification, or proof that every question within a layer was established; STL or ATLAS listed as a depth may have yielded only an unresolved binding.
